# BMS Web 菜单与页面说明

## 一、本次调整

1. **控制策略** → **电池配置**：仅保留一级菜单，无子菜单；对应页面为「电池配置」。
2. **模板管理** → **历史数据**：子菜单为 **数据查询**、**事件记录**、**告警记录**。
3. **日志页**：已去掉（后端不返回日志管理菜单，且 SQL 可隐藏日志相关菜单）。

## 二、前端页面与路由对应关系

| 菜单名称   | 前端组件路径                     | 说明           |
|------------|----------------------------------|----------------|
| 电池配置   | `views/battery/config/index.vue` | 电池系统参数配置 |
| 数据查询   | `views/history/timed/index.vue`  | 历史数据查询   |
| 事件记录   | `views/history/event/index.vue`  | 事件记录       |
| 告警记录   | `views/history/alarm/index.vue`  | 告警记录       |

菜单与路由由**后端接口**返回；后端菜单表 `sys_menu` 中 `component` 需与上表一致（如 `battery/config/index`、`history/alarm/index`）。

## 三、菜单为什么没改？数据库是什么？

- **菜单名称来自后端接口**：前端侧边栏的菜单是后端根据**数据库表 `sys_menu`** 生成的，接口返回什么名字，页面就显示什么名字。所以改菜单名、子菜单、是否显示，都要在**数据库里改**（或通过系统管理里的「菜单管理」改，本质也是改库）。
- **本项目的库是 SQLite**（不是 MySQL）。配置文件里：`DB_TYPE = 'sqlite'`，`DB_URL_WEB = 'sqlite:///../web.db'`。菜单数据在 **web.db** 这个 SQLite 文件里（路径相对后端运行目录，一般在项目根或后端上一级）。

## 四、如何应用菜单修改

### 方式 1：用 Python 脚本直接改数据库（推荐）

在**后端目录**下执行（会连接项目使用的 **web.db**，直接修改 `sys_menu` 表）：

```bash
cd web-backend
python fix_bms_menu_and_seed.py
```

脚本会：把「控制策略」改为「电池配置」并设为单页、隐藏其下子菜单；把「模板管理」改为「历史数据」，只保留「数据查询」「事件记录」「告警记录」三个子菜单并修正 path/component；隐藏「日志管理」及其子菜单。执行完成后**重新登录**或**刷新页面**即可看到菜单变化。

- 若提示「数据库文件不存在」，说明还没生成过 web.db，可先正常启动一次后端再执行，或检查 `.env.dev` 里 `DB_URL_WEB` 的路径（一般为 `../web.db`，即项目根下的 web.db）。

### 方式 2：用数据库工具执行 SQL（SQLite）

1. 找到 **web.db** 文件位置：后端运行目录的上一级，或 `.env.dev` 里 `DB_URL_WEB` 中 `sqlite:///` 后面的路径（如 `../web.db` 表示上一级目录下的 `web.db`）。
2. 用 **SQLite 工具**打开 web.db，例如：
   - **DB Browser for SQLite**：打开 web.db → 选「Execute SQL」→ 粘贴并执行 `web-backend/sql/bms_menu_migration.sql` 里的语句。
   - **VS Code 插件 SQLite**：打开 web.db，新建查询，粘贴 SQL 后执行。
   - **命令行**：在包含 web.db 的目录执行  
     `sqlite3 web.db < 路径/web-backend/sql/bms_menu_migration.sql`
3. 执行完后重新登录或刷新页面查看菜单。

### 方式 3：在 菜单管理 里手动改

见下方「五、在菜单管理里手动改」。

### 五、在 菜单管理 中手动改

1. **电池配置**：找到原「控制策略」，改为菜单名称「电池配置」，删除或隐藏其下所有子菜单，并设置：
   - 菜单类型：菜单
   - 路由地址：`battery-config`
   - 组件路径：`battery/config/index`
2. **历史数据**：找到原「模板管理」，改名为「历史数据」，其下只保留三个子菜单并设置：
   - 数据查询：组件 `history/timed/index`，路由 `query`
   - 事件记录：组件 `history/event/index`，路由 `event`
   - 告警记录：组件 `history/alarm/index`，路由 `alarm`
3. **日志**：找到「日志管理」，将「显示状态」设为隐藏，或停用。

## 六、风格与 BMS 模拟数据

- **电池配置**、**数据查询**、**事件记录**、**告警记录** 页面均按 BMS 电源管理系统 Web 端操作习惯编写，与现有「设备监控」「系统概览」风格一致（卡片、表格、查询表单、导出等）。
- **模拟数据**：系统概览、设备监控 已在各自页面内写有 BMS 相关 mock 数据（电压、电流、SOC、簇数、告警等）；历史数据（数据查询/事件记录/告警记录）会请求后端 `/history/timed-data`、`/history/event-data`，若后端暂无数据可先依赖前端示例或等业务库接入后再查真实数据。
- 若后续需对接真实接口，只需在对应页面中替换为实际 API 即可。

## 七、自己改数据库的步骤（SQLite）

1. **找到 web.db**：在项目根目录或 `web-backend` 上一级，文件名 `web.db`（由 `.env.dev` 里 `DB_URL_WEB = 'sqlite:///../web.db'` 决定）。
2. **用工具打开**：用 DB Browser for SQLite 或 VS Code 的 SQLite 插件打开 `web.db`。
3. **改菜单**：在 `sys_menu` 表中：
   - `menu_name`：显示名称（如改为「电池配置」「历史数据」）。
   - `visible`：`0` 显示，`1` 隐藏。
   - `parent_id`：子菜单的父级菜单 ID（如 2016、2017、2018 的 `parent_id = 2012` 表示挂在历史数据下）。
   - `path`、`component`：路由和前端组件路径（如 `battery-config`、`battery/config/index`）。
4. 保存后重新登录或刷新页面。
